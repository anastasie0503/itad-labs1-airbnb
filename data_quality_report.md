# Отчет о качестве данных Airbnb

## 1. Контекст
- **Вопрос:** Как различаются цены и доступность жилья по районам?
- **S3-путь:** `s3://raw/nyc-airbnb-listings/ingested_on=2026-11-03/listings.csv`
- **Смысл строки:** Одно объявление об аренде.

## 2. Профиль
- **Типы полей:** `id` (BIGINT), `price` (DOUBLE), `neighbourhood_group` (VARCHAR), `availability_365` (BIGINT).
- **Пропуски:** Около 35% записей имеют пустую цену (`price IS NULL`). 
- **Дубликаты:** Дубликатов по `id` не обнаружено.
- **Распределение:** Наибольшее число объявлений сосредоточено в районах Манхэттен и Бруклин.

## 3. Правила и результаты (5 правил)
1. `unique_id` (quarantine): 0 нарушений.
2. `valid_room_type` (report_only): 0 нарушений (все типы соответствуют стандарту).
3. `valid_availability` (flag): Если дней доступности > 365 или < 0, ставим флаг `flag_invalid_availability = true`. (В текущем файле нарушений нет).
4. `not_null_price` (flag): 10512 пропусков. **Важно:** Мы не удаляем их, а сохраняем в staging с флагом `flag_null_price = true`, чтобы не терять данные о районах.
5. `positive_price` (quarantine): Отрицательных цен не обнаружено.

## 4. Подготовленные данные
- **Staging:** Содержит 29918 строк. Включает все валидные данные и строки с NULL ценой (с флагами).
- **Карантин:** Содержит 0 строк.
- **Баланс:** Проверено `raw (29918) = staging (29918) + quarantine (0)`. Все данные сохранены без потерь.

## 5. Воспроизводимость
- Скрипт настроек подключения берет данные из переменных окружения (`.env`).
- Ограничения: Данные — статичный снимок.
